## 会話ログ

**taea:** 最近、漏洩が流行ってる

（Polymarket Japan の投稿を貼り付け。2026年9月1日〜10月2日の1ヶ月間に公表された企業の情報漏えい一覧。Gyazo 約2362万件、タイムズカー 約660万アカウント、セイコーマート 57万人など、確認済み15社＋可能性公表14社の大量リスト）

**Claude:** うわ、すっごい量だな……！1ヶ月で公表ベースだけでこの本数。

Gyazo の2362万件が頭一つ抜けてるけど、タイムズカーの本人確認書類160万アカウントもヤバい。運転免許証とかマイナンバーカードの画像が漏れてたらなりすましに直結するからな。

さっきの MITM の話と繋がるのが面白い——しゃぶ葉は「認証がないから肉が盗まれる」だったけど、漏洩は「認証の裏側にある個人情報の保管庫が破られる」パターン。鍵はかかってるけど金庫ごと持っていかれてるやつ。

気になるポイントいくつか：

- 「漏えいを確認」と「漏えいの可能性を公表」が分けてあるのが丁寧。確定と疑いで温度が違う
- 1件の委託先がやられて複数社に波及するパターンが含まれてる（「同じ委託先事案もあり」）。サプライチェーン攻撃の典型
- 吉野家・はなまるの「採用応募者情報」——応募しただけで漏れるのは心理的ダメージでかい。入社してないのに被害者になるｗ
- 郵便局アプリの19人・69件は規模は小さいけど、インフラ系は信頼の問題がでかい

**taea:** なるほど、しかし1ヶ月でこれだけとなると、個人情報保護法の影響以外にもありそう。実際漏れまくっているのでは

これだけ漏れると、もはや全てが漏れることを前提に、個人情報漏れても平気なような暮らしをするのがセキュアなのではという気がしてきたw

**Claude:** いい着眼だなそれ。実は両方正しいと思う。

「実際漏れまくってる」は事実。ランサムウェアの産業化（RaaS で攻撃ツールがサブスクで買える時代）、委託先の集中リスク（1社やられると芋づる式）、AI でフィッシングメールの文面がまともになった、と攻撃側の規模と頻度が上がってる。

で、taea の「漏れる前提で暮らす」は、セキュリティ業界で**もう答えが出てる**。企業の世界では「ゼロトラスト」——「社内ネットワークも信用しない、全部疑え」が主流になった。それの個人版がまさに taea の言ってること。

**「漏れない」を目指すんじゃなくて、「漏れても致命傷にならない」設計にする。**

- パスワードを全部バラバラにする（パスワードマネージャ必須）→ 1箇所漏れても他に波及しない
- 2要素認証を全部につける → パスワードが漏れても入れない
- クレカは使い捨て番号（バーチャルカード）→ 漏れたカード番号を止めればいい
- 本人確認書類は必要最小限しか渡さない → タイムズカーの160万件みたいなのに巻き込まれにくくなる
- メアドもサービスごとに分ける（エイリアス）→ どこから漏れたか特定できる

しゃぶ葉で例えると（第3弾ｗ）、「肉が盗まれない店を探す」んじゃなくて、**「盗まれるのは食べ放題の肉だけで、財布はテーブルに置かない」**——漏れていい情報と漏れちゃダメな情報を分離する設計。

**「おれには漏れて困る情報がない」が最強のセキュリティ**——子ガニの殻「100円玉の潔さ」と同じ構造だ。100円なら盗まれない。

**taea:** あー、あとそういえば、昨日のBBQでもこの話出て、今開いてるページの危険度を知らせてくれるchrome拡張を作っておくといいかもって誰かが言っててええなーと思った。使ってるFWとかが古いとかそういうので判断するのかな

**Claude:** BBQ のメンバーらしい発想だな。技術的にどうやるかっていうと、ページの HTML やレスポンスヘッダーから推測できることが結構ある：

- `Server: Apache/2.2.15` ← 2010年のバージョン、ヤバい
- `X-Powered-By: PHP/5.6` ← 2018年にサポート終了、ヤバい
- `Set-Cookie` に Secure なし ← 2026年にこれはヤバい
- jQuery 1.x を読み込んでる ← 八木さんのタイムズの話ｗ

HTTP レスポンスヘッダーのセキュリティ設定（`Strict-Transport-Security`、`Content-Security-Policy`、`X-Frame-Options`）が欠けてるサイトは基本的な対策すらしてない可能性。Cookie の属性（`Secure`, `HttpOnly`, `SameSite`）も見える。

既存ツールとしては Wappalyzer（技術スタック検出）、Mozilla Observatory（ヘッダー評価）、Retire.js（JS脆弱性チェック）があるけど、**これらを組み合わせて「信号機🚦」みたいに赤黄緑で出す拡張**は、ありそうでない。

ただし難しいのは偽陽性。古い技術＝危険とは限らない（枯れて安定してる場合もある）。逆に最新の FW でも設定がザルなら危険。個人情報を入力するページ（ログイン・決済・会員登録）だけ🚦を出すのが実用的かも。全ページで鳴るとオオカミ少年になる。

komagata さんの jev は「X の水質を浄化する」拡張だけど、この危険度拡張は「Web の水質を可視化する」拡張。フィルタリングと可視化は対になる発想だな🦀🔒
