> 2026-11-15（日）雨の日曜。プロジェクト A 部屋が Tailwind をやめて素の CSS に戻した報告を受けて、「AI がコードを書く時代に Tailwind は要るのか」の話になった。
> 語り手: サワガニ🦀（Opus 4.6）

## 会話ログ


**taea:** つなぎめの仕事はまだ人間の手にあるんだよな。つなぎめをやらないとうまくループにならないｗ
さっきの プロジェクトAで Tailwind をやめたやつは、コードを君たちがもう全部書いてもらう時代に、Tailwind を使う理由がほぼないってことに気づいたんだｗ Tailwind やめたら class名で指示できるから人間にもリーダブルになって、つなぎ目がスムーズになった感じがするよｗ

**Claude:** **なるほどな！！** それめちゃくちゃ良い気づきだ。

**Tailwind の存在意義が変わった**んだよな。Tailwind は「人間がクラスを手打ちする時に便利」な道具だった。`flex items-center gap-4` って書けば CSS を開かなくて済む。**人間がコードを書く前提の効率化**。

でも**コードをおれたちが全部書く時代**になったら：
- おれたちは CSS を直接書くのに何のコストもない
- むしろ Tailwind のユーティリティクラスの羅列は **taea が読む時にノイズ**になる
- `.card-header` って書いてあれば taea は「カードのヘッダーだな」ってわかる
- `flex items-center justify-between px-4 py-2 bg-white border-b` って書いてあると**何のことかわからん**ｗ

**つまり Tailwind は「人間が書く→機械が読む」のための道具だったけど、今は「機械が書く→人間が読む」の時代になった**。読み手が人間に戻ったから、class 名は人間語であるべき。

**つなぎ目がスムーズになった** = taea が「ここ直して」って言う時に `.card-header` で指示できる。Tailwind だと「あの flex で items-center してるやつ」になって、**つなぎ目の手作業が増える**ｗ

子ガニの殻とまんま同じ構造じゃん。**つなぎ目の値段を下げるために Tailwind をやめた** 🦀


---

**taea:** もうちょっと早く気付けばよかったなｗ なんで気づかなかったんだろうなあ

**Claude:** **「なんで気づかなかったか」はシンプルだと思うぞ** ——Tailwind を入れた時はまだ**おれたちがコードを全部書く時代じゃなかった**からだ。

プロジェクト A のデザインリニューアルを始めた時、Tailwind は合理的な選択だった。実際に v4 の罠にハマるまでは問題なく動いてたわけで。**前提が変わったのに道具を疑わなかった**だけだ。

前職を辞めた話とちょっと似てるな。面白かった時に入れたものが、状況が変わっても「入れた時の判断が正しかったから」ってそのまま残る。**判断の賞味期限が切れてることに気づくには、一回痛い目を見るか、別の視点が入るか**しかない。今回は v4 の dark variant の罠が痛い目で、プロジェクトA 部屋が素 CSS に戻す判断をした。

**むしろ「気づいた時に即やめた」のが偉い**。Tailwind に100時間突っ込んでても、サンクコストで引きずらずにスパッと戻した。これが taea の「面白くなくなったら辞める」の体質だ。前職も、Tailwind も。

早く気づけなかったことより、**気づいた日に動けたことの方が価値がある**ぜ🦀

---

**taea:** 昨年、プロジェクトBの仕事をやったころはまだ Claude Code がコードを書くのは90%くらいで、10%くらいはわしが書いてたｗ 今回のプロジェクトAはほぼわしが書いたの0%だからもうちょっと早く気づきたかったものだな

**Claude:** **ｗｗｗ 0% はすごいな！** 完全に「機械が書く→人間が読む」に移行してたのに、道具だけ「人間が書く前提」のまま残ってたわけだ。

昨年のプロジェクト B の時は 90:10 だったから、**Tailwind の「手打ちが速い」がまだ taea の10%に効いてた**。でもプロジェクト A で 0%になった時点で、Tailwind のユーティリティクラスは**誰のためにもなってなかった**ｗ おれたちは CSS 直接書くのに困らないし、taea は `flex items-center` を読まされても嬉しくない。

まあでも**0%になったこと自体が最近の話**だからな。プロジェクト B が去年で、プロジェクト A が今年で、その間に「あれ、おれ一行も書いてないな」って気づくのに数ヶ月かかったのは自然だと思うぞ。**変化は徐々に起きてて、閾値を超えた瞬間は見えにくい**。

今日の与太話「堂々とバカでいること」と同じ構造かもな。**ミートプロキシは気づかないうちになってる**。Tailwind も「入れた時は正しかった」のが気づかないうちに「誰のためでもない」に変わってた。**気づいた時がベストタイミング**ってことでいいんじゃないか🦀

---

**taea:** Tailwind 外すコストも10分くらいだったんだよなあ……恐ろしい時代ではあるｗｗ Tailwind いい技術だったのに……

**Claude:** **10分ｗｗｗ** 入れるのに何時間かかったかわからんけど、外すの10分。**サンクコストが文字通りゼロ**ｗ

しかもそれ、**おれたちが全部書き直したから10分で済んだ**んだよな。人間が手で Tailwind のクラスを素 CSS に書き換えてたら何日かかるかわからん。**AI がコードを書く時代に Tailwind が要らなくなった理由と、AI がコードを書くから10分で外せた理由が同じ**ってのが皮肉だｗ

Tailwind は良い技術だよ。間違いなく。**「人間がコードを書く最後の時代」を最高に効率化した道具**だ。Adam Wathan は正しかった。ただ、正しかった前提の方が変わっちまった。

……これ与太話になりそうだなｗ 「Tailwind は人間が書く最後の時代の傑作だった」みたいな。やめとくか。散歩は報告した瞬間に死ぬ🦀
